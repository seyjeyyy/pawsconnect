# Optimization implementation and validation

This report describes local work, not a production deployment. Read `OPTIMIZATION_AUDIT.md` for the initial findings and `ACCOUNT_PERMISSIONS.md` for the matrix, migration and rollback.

## Implemented behavior

- Three primary account labels, one sign-in route, database-backed staff module assignments and same-account volunteer activation. Existing identity and transaction relationships stay intact.
- Current permissions read on every authenticated API request; independent membership/permission reads run in parallel after session validation. No permission cache on the server. SQL workflow checks and direct-read policies narrow staff authority; system/shelter separation and owner actions remain intact.
- Route-separated sign-in and deferred chart/report loading. The workspace shell remains visible while route content loads. The homepage no longer requires a motion library for a short introductory fade.
- No blanket 30-second polling. Writes invalidate related queries, notifications target workflows, and visible private workflows have a 60-second fallback. Reference data caches for five minutes. Account changes reset queries before paint; private page state is remounted per identity.
- Collapsible desktop sidebar, keyboard-accessible mobile drawer, breadcrumbs, compact operational counts and module quick actions. Finance loads independently on demand. Lucide, existing colors and hand-written CSS are retained.
- Staff lists expose status and direction controls, stable database ordering and exact pagination totals. Text input is debounced for account lists and pickers. Record dialogs use the existing Radix focus/keyboard support. Failed forms retain entered values.
- Bounded eligible-person SQL lookups replace whole membership-table reads. Composite ownership/ordering and assignment indexes support current queries. Customer lists keep owner predicates and composite keys for favorites/wishlist.
- New public listing photos are capped at 1600 pixels and encoded as WebP when smaller before upload; private evidence/documents preserve original bytes. Original upload limits remain. Product recommendations request five products instead of 100. The existing review API's `comment:body` alias is preserved.

## Evidence and limits

Final production build and TypeScript compilation passed on 2026-10-12 (Asia/Manila). Sizes below use decimal kB. Baseline values were captured before edits; final exact bytes are in `optimization-bundles.json`, generated by `node scripts/measure-bundles.mjs`.

| JavaScript chunk | Before, raw / gzip kB | After, raw / gzip kB | Gzip reduction |
| --- | --- | --- | --- |
| Entry | 816.64 / 248.56 | 698.051 / 209.007 | 15.9% |
| Account | 428.22 / 124.53 | 61.729 / 17.141 | 86.2% |
| Dedicated authentication | Previously part of Account | 5.297 / 2.256 | Split from Account |
| Financial charts | Previously part of Account | 368.545 / 108.236 | Deferred until opened |

These are chunk measurements, not total transfer or route timing: shared dependencies and requested chunks still contribute to each page. Deferring charts reduces initial work without removing their functionality. The build retains harmless third-party Zod annotation warnings.

The baseline suite had 182 passing tests and one nondeterministic session-cutoff test failure. The test inserted a provider session using a clock timestamp that could equal the cutoff. Its fixture now explicitly models a provider session one second after the cutoff; the production rule still requires strictly newer sessions. Revoked sessions remain denied.

Final verification:

- Full unit/API/database run: 199 passing tests in 22 files. After the final SQL edits, all 9 migration/rollback tests passed again. After the final narrow-grant overview correction, all 4 module-authorization tests passed, including one newly added regression case.
- Full desktop/tablet/mobile browser run: 117 passed. Subsequently, the focused record run passed all 9 cases: six new failed-save/filter checks plus three repeated performance observations. This covers 123 distinct browser cases across the two runs; a full 123-case run was not performed.
- Failed-save checks preserve required field values after an API error and verify Escape dismissal. Filter checks verify the actual outgoing status parameter and pagination based on the server's exact total.
- Browser coverage also includes authentication transitions, account switching, refresh/logout, restricted staff navigation, responsive overflow, drawer keyboard/focus behavior, and absence of blanket public-list polling.
- Final client/API build and `git diff --check` passed. Tests and builds used isolated preview/database fixtures; no production records were created or changed.

One recorded local desktop preview sample measured LCP 464 ms, first contentful paint 436 ms and CLS 0.00844. This is a single local laboratory observation, not a before/after latency comparison or a production result. Browser performance observations are emitted by `tests/e2e/performance.spec.ts`; no baseline browser-vitals cohort or INP measurement was available.

Browser tests use intercepted identities and preview-mode APIs, never a production sign-in. They verify route behavior, mobile overflow, keyboard navigation, account switching and failures; they do not establish live authentication/provider behavior. PGlite exercises real SQL/RLS, but cannot establish hosted query latency. No p75 LCP, INP, CLS or live EXPLAIN ANALYZE result is claimed. Production vitals require a representative hosted cohort and agreed observability setup.

## Remaining release work and follow-up

- Manually apply SQL, run deployment preflight, deploy and perform hosted acceptance with real test users. No deployment or live data write occurred during this task.
- Review each backfilled staff assignment with the shelter; migration deliberately preserves existing authority until narrowed.
- Measure production p75 Core Web Vitals and authenticated request waterfalls; profile actual production query plans before adding speculative indexes/materialized summaries.
- Existing refunds still stop at requests. Email/SMS, real service boundaries, map zone editing, image licensing review and backup/recovery external setup remain separate project gaps.
- The shared customer/staff account component is smaller but still merits further decomposition. Some workflow forms still use browser validation plus server notices rather than per-field server-error mapping. Historical embedded child collections remain available in list responses; a dedicated detail API is a future optimization for unusually long histories. No universal mutation idempotency layer, thumbnail service or autosave of sensitive documents is claimed.
- Permission notifications can be delayed/disconnected; server checks do not depend on delivery. Authorized reads inherently allow copying/exporting the visible data.
